## 用户体验目标

用户连续使用 Bot 时，可以直接说「以后记住」「这条已经变了」「把这件事忘掉」。用户需要能看到保存结果、来源和可见范围。Bot 应在新的对话中主动使用已经保存的事实，遇到具体往事时按需检索原话。用户结束一段有价值的工作后，Bot 能在后台提炼少量耐用结论，提醒用户查看需要确认的变更。重复完成相似工作时，Bot 可以找到经过验证的做法，并用它指导新的任务。

例如，用户在私聊说「每次发版先做预检」，Bot 将这个项目约定保存到正确的项目。下周用户说「我们把预检换成 `release check` 了」，Bot 更新现有条目。再开对话时，它使用新的命令。用户问「上次为什么要加这一步」，Bot 搜到当时的讨论，并能带你回到原话。它复盘时若发现发版流程可复用，可以自动保存一份有验证依据的技能，下次发版时按需加载。群里的 Bot 只能使用该群可见的对话、笔记和技能。

## 记忆写入和注入

建议由 BaoCode 宿主持有统一的记忆服务。Bot 工具、桌面编辑、后台复盘都走同一套授权、变更和提示刷新逻辑。用户发话、宿主收到任务状态、编程 Agent 给出结果是不同的证据类型，保存时要保留区分。

一条记忆包含稳定 ID、内容、归属 Bot、作用域、类型、来源消息或任务、更新时间、修订号以及是否由用户固定。类型覆盖用户偏好、Bot 自我信息、人物印象和项目事实。长期笔记、当前 `Now:` 状态、待办提醒、历史消息与可执行技能分别使用各自的存储和生命周期。已有身份设定和共享用户资料可以显式标记为用户提供的内容。

- 模型工具提供列表、添加、定点修改和删除。修改和删除使用 ID 与预期修订号。模型可以在一个事务里合并几条重复笔记。相同内容的重复请求应具备幂等性。
- 用户明确要求记住、纠正或忘掉时，Bot 走对应动作并返回实际结果。模型主动发现可能矛盾的旧结论时，提交带来源的修改。如果用户和后台同时编辑，宿主退回过期提案，供复查后重新提交。
- 常驻记忆批量写入按最终大小校验，超预算时返回当前条目和需要释放的空间，让 Bot 把合并与新增放在同一批提交。旧数据导入或缩小预算时保留超出的条目，桌面标明常驻与待整理状态。各范围的默认容量和短上下文装载顺序见下文。
- 注入使用确定顺序和稳定快照，方便复用模型前缀缓存。普通编辑默认在新会话、手动刷新和支持的实时压缩边界装载。冷启动恢复该会话上次装载的版本。「忘掉一条」是显式撤回，按下文的快照失效规则生效。手动刷新保留会话 ID 和历史。工具在本轮返回写入结果和新值。原聊天仍可能包含旧说法，提示要明确当前确认的条目是最新依据。
- 提供「开启新对话」入口。它停用当前上下文，保留老对话和来源链接，为同一个 Bot 建立新会话并加载最新快照。历史续聊仅适用于已经隔离的同范围会话。升级前的混合会话只供回看。清空聊天继续作为独立操作。
- 建议由事务型本地存储管理结构化记忆和待审变更，并以 Markdown 提供导入、导出和可查看副本。现有纯文本编辑接口在迁移期通过相同服务读写。实现前核对现有 Bot 文件的编辑方式，由统一服务协调所有写入。

### 条目范围、容量与授权

宿主用 `Bot ID + 范围类型 + 范围 ID` 定位记忆库。条目 ID 在库内稳定且不复用。更新、固定和撤回使用预期修订号。来源记录证据类型和原始定位，允许导入项以迁移记录为来源。项目由宿主分配稳定 ID，显式移动保留原 ID，删除后在同一路径重新新建会获得新 ID。一次写入事务只涉及一个库，状态和重试结果由宿主持有。

| 范围 | 保存内容与默认预算 | 装载条件 |
|---|---|---|
| 私聊 | 用户偏好 1,375 字符。自我信息与人物印象合计 2,200 字符，均支持逐条修订、固定和撤回。 | 该 Bot 的私聊。人物笔记带稳定人物键，重名须由用户选择。 |
| 单群 | 每个 Bot 在每个群的事实及获准共享的条目合计 1,375 字符，沿用当前群笔记容量。 | Bot 仍是该群成员时，只在该群装载。 |
| 本地项目 | 每个 Bot 在每个授权项目的事实合计 2,200 字符，例如发版约定和已确认的环境约束。 | 正在执行明确关联该 Bot 和项目的任务，且用户授权仍有效。通过项目选择器关联普通项目任务。 |

预算按最终渲染正文的 Unicode 字符计，包含列表标记和换行。默认先装载固定条目，同组维持保存顺序，超额的旧条目留在库中供整理。纯删除可以逐步降低超额。上下文不足时，运行时先为用户输入、固定提示、工具定义和模型输出留出预算，再按同一顺序装载能够完整容纳的条目。条目固定仍受可用预算约束。快照记录实际装载结果，管理页可说明因容量或上下文省略的条目。

共享用户资料、Bot 身份和 `Now:` 仍各自管理。长期人物印象只写入当前已验证的范围，群成员发言不会写成私聊主人的偏好。用户共享一条私聊或项目记忆时，宿主登记来源条目及修订、目标范围和授权人，在目标预算内创建有来源的条目。更新后的正文需要用户重新确认才能共享。撤回共享、源条目被忘记或访问资格失效时，目标条目按快照撤回流程停止注入。已投递的普通聊天消息按消息保留规则处理。

## 历史回忆与作用域

宿主从已经落盘的消息构建可重建的本地全文索引。索引行保存来源类型、会话和消息 ID、角色、作用域和时间。默认索引用户发言和可见回复。开发日志、工具输出和隐藏推理使用各自的保留与授权策略。精确引用留在原始记录中，索引提供命中片段与可定位的原始 ID。

- 工具支持关键词、时间、项目、会话或聊天范围，返回若干命中和继续翻页的游标。用户可以点开原话，模型决定是否需要向前或向后浏览。历史索引的可见范围从当前上下文和宿主授权计算，搜索参数只负责进一步缩小范围。
- 中文需要单独验收。用本机 SQLite 3.51.0 的合成样本验证，trigram `MATCH` 可以找到「改喝红茶」，找不到两字词「红茶」，`LIKE` 可以找到后者。建议测试 CJK 分词或带权限和时间上限的短串回退，并覆盖路径、版本号、混合语言和跨标点短语。这个探针验证了本机 SQLite 行为，应用绑定与跨平台打包仍需验证。
- 基线版本把同一 Bot 的私聊和群聊写入同一模型会话。拆分后每个 Bot 保持统一身份，私聊与各群使用独立的模型上下文，各自只装载当前可用的记忆。用户在私聊明确选择一个自己可见的群，才引用该群往事。群里只看该群及用户明确分享的记忆。
- 作用域包括宿主上的 Bot/用户、项目、私聊和单群。Link 身份和成员资格在上位服务层校验。群聊可用的工具也必须受到这条边界约束，涵盖通用文件读取、会话查询和能访问宿主数据的其他能力。旧的混合会话仅限有权的宿主用户查看，历史作用域明确的独立群记录可按原范围索引。

### 桌面宿主的运行方式

1. **按场合选择会话。** 用 Bot ID 与聊天范围标识宿主线程。每个 Bot 有一个私聊范围，以及它加入的每个群各自的范围。私聊入口取得私聊线程，轮到 Bot 在群中发言时取得「该群 × 该 Bot」线程。模型选择、头像、身份和管理设置仍按 Bot 生效。宿主持久化范围到线程的映射，重启后按映射恢复。私聊入口沿用 `threadFor(bot)` 的入口形态，群聊显式传入群 ID。群运行目录使用宿主管理的独立路径，保留现有 Bot 资料目录作为身份来源。新旧目录有独立迁移规则，避开启动时仍会扫除的旧群成员目录。创建、恢复与会话替换都重新建立对应范围的监听。[现有线程选择](/Users/yimingd/Projects/baocode/lib/bots/bots.dart#L607) · [旧群会话清理](/Users/yimingd/Projects/baocode/lib/bots/bot_groups.dart#L148)
2. **发消息时就记录目标。** 私聊发送、群聊轮转和主动唤醒都在宿主记录消息来源、目标和轮次 ID。模型结束后按这次轮次的绑定发送结果，超时和图片缓冲也绑定同一轮，避免迟到的结果发错群。私聊保持现有基于 Bot 的已读与未读状态，群聊继续由群记录生成消息、序号、引用、输入状态和推送。默认保留同一个 Bot 同一时间只处理一轮的调度规则，群聊轮转继续排队。[群回合启动与调度](/Users/yimingd/Projects/baocode/lib/bots/bot_groups.dart#L913)
3. **在构造模型请求时限制可见内容。** 每个范围从其自己的会话、日记、历史查询与记忆快照取数据。群聊可以得到同一群的最近对话和明确共享的 Bot 资料。私聊中的用户偏好或项目数据需要明确分享才能进入一个群。私聊主人可以指名让 Bot 搜某个自己可见的群。宿主校验查阅权限并把结果送进私聊。
4. **让工具遵守同一范围。** 对搜索、原话读取、发往其他场合的消息、通用文件和会话访问，以及后台复盘使用宿主提供的轮次身份。自定义工具也按范围授权。群聊可用现有工具读取范围内的群记录，无法限定数据范围的工具需要由宿主拒绝用于群聊。群派发的输出默认发往该群。群聊通过 `bot_send` 合法发送私聊时，宿主生成一条有投递 ID 的私聊消息，供私聊历史、未读和时间线消费，重试时按 ID 去重。目前这类私信依靠共用会话里的工具结果显示。[现有跨场合发送](/Users/yimingd/Projects/baocode/lib/bots/bot_tools.dart#L491) · [现有私聊投影](/Users/yimingd/Projects/baocode/lib/link/chat_codec.dart#L34)

### 升级与老聊天

升级时把旧混合会话保留为历史来源，按已经可识别的私聊段生成私聊历史视图。新的私聊运行时从受限的启动上下文恢复，旧混合记录不作为模型的续聊输入。群聊继续读自己的持久化记录，保留消息序号、引用和附件映射。无法确定范围的旧内容由有权的宿主用户查阅，避免猜测归属后把它发给模型或出现在群里。

旧版客户端打开私聊时，从宿主的统一私聊视图得到最近消息和更早分页。首次升级时尽量沿用可识别的旧私聊 ID、消息条目编码和已有回复标签。新视图与 Link 请求携带的 `have` 摘要不一致时返回完整会话快照替换旧窗口。后续更换活动对话时按下文的 Link 会话边界分配别名并校验操作。[缓存对齐](/Users/yimingd/Projects/baocode/lib/link/workspace_bridge.dart#L1753)
「清空私聊」只清理私聊活动上下文、对应历史视图及其索引。共享的群日志和其他范围的运行时各自保留。删除群或移除成员后清理对应的群运行上下文及可访问的索引，并使待复盘的来源失效。现有消息或群组授权是标记历史范围的依据。

### 宿主 Link 兼容

## 后台复盘与技能

复盘使用当前作用域内已经稳定提交的对话、任务终态和相应证据。建议把它作为独立的宿主任务运行。手动「整理记忆」提供可选关注点。自动复盘默认在累计 10 个有效用户轮次或 10 次含工具调用的迭代后触发，并在前台回复完成后执行。开启新会话和压缩会话会更新记忆注入的边界。按任务完成事件额外触发复盘作为 BaoCode 的可选设置，默认采用与 Hermes 一样的轮次和工具调用阈值。外部运行时只统计可观测的事件。

为每个会话记录上次处理的位置，手动触发以外的重叠请求合并处理同一段消息。作业使用独立 ID 和有上限的重试。宿主重启可恢复已接收的任务，前台聊天优先使用模型资源。预设限额覆盖每次复盘的消息量、输入和输出预算及并发数。默认复用前台模型，用户可指定单独的复盘模型。

模型输出结构化提案，每条包含新增、替换、删除或技能草案，附上依据、归属范围和当前条目修订号。宿主校验来源可见性、大小、重复和冲突，再决定是否提交。对话中的引用和工具回显作为证据处理，写入能力由复盘运行器限定。提交逻辑复用前台记忆服务，避免一次复盘直接改写整份文件。

对齐 Hermes 的记忆写入默认值。前台操作和无冲突的后台新增条目直接保存，并在状态里可见。后台替换、删除进入待审。用户可以开启全部待审或关闭自动复盘，仍可手动运行。扩大可见范围由用户明确授权。提案只被采纳一次，重复复盘后发现同一事实时合并证据。[Hermes 记忆写入设置](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tools/memory_tool.py#L179)

技能记录包含适用项目、触发条件、验证过的步骤、验证结果、依赖和来源。复盘先检查相近的已有技能，优先更新现有做法。对齐 Hermes 的 `skills.write_approval: false`，通过项目作用域、锁定状态和修订检查的技能变更默认写入，并保留来源和变更记录。用户可以开启技能待审，在桌面查看差异再逐项确认。后续会话只按任务的项目和适用条件加载相关技能，执行沿用项目已有工具权限。自动写入服务校验技能文件和运行时能力，禁止技能通过 front matter 新授工具权限。项目约定可以作为事实，含条件和步骤的成熟做法才进入技能。[Hermes 技能写入设置](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/features/skills.md#L669)

技能维护参考 Hermes Curator。它默认跟踪自建技能的使用，14 天未用标记为陈旧，30 天可归档，固定的技能可以免于自动归档。可选的模型合并和恢复是独立能力。BaoCode 可给模型产出的技能提供固定、锁定、可恢复归档及修订记录，合并只在有审阅的情况下应用。代码库已有技能、用户手写技能和外部安装技能沿用各自的管理权限。[Hermes Curator](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/features/curator.md#L33)

### 项目证据、技能维护和复盘成本

- 宿主在接受项目任务时持久化任务 ID、Bot、授权项目、提交方和证据起点。完成事件使用同一个任务 ID，接收与补录共用去重。Bot 委派任务使用已有项目授权。普通项目会话可由用户明确关联 Bot 和选定任务范围，历史默认保持原范围。宿主重启后从任务记录和已提交的会话证据恢复检查点。取消、失败或缺少验证证据的任务可以保留回顾记录，成功验证才可自动生成可执行技能。
- 项目约定使用项目事实库。技能证据分别记录用户要求、助手回报和宿主可核实的步骤或验证结果。助手声称成功的文字不能单独作为已验证结果。重复事实在同一范围按精确规范化键合并来源，保留独立用户事实的出处。相近事实或技能可生成带修订号的合并提案，批准后提交，拒绝记录随被审修订保留。
- 技能保存按项目、名称和预期修订校验。技能正文来自已确认版本，权限沿用项目授权。授权任务按项目和触发条件选择适用技能，运行时确认装载后才更新使用时间。14 天未用标为陈旧，30 天归档，固定项继续保留，锁定项的修改和归档须先解除锁定。归档保留来源及修订历史，恢复先校验名称占用和项目权限。项目撤权后停止装载并清除待审来源，用户可以查看仍有权限的本地修订。
- 设置展示复盘模型、每批输入和输出上限、实际请求用量及失败原因。根据所选模型计价、上下文上限及重试上限显示一次作业的预计费用上限。价格未知时显示用量上限和「价格未知」。自动暂停后停止新后台作业，已接收的作业可在恢复后从检查点继续，手动复盘继续可用。

### 外部提供方

外部提供方默认关闭，按宿主和 Bot 显式启用。首个交付支持用户明确发起的只读检索，设置标明端点、发送字段、已知保留规则和查询关闭方式。只发送指定查询，提供方返回的文字按检索结果处理。停用后拒绝新请求，进行中的请求返回时也要重新核验授权。提供方不可用时继续使用本地记忆。外部写入、远端删除和双向同步作为后续可选能力，接入时单独定义能力声明、数据保留和删除回执。Hermes 内置配置和各提供方分别验收。

## 服务接口与一致性

| 入口 | 输入和结果 | 谁拥有写入权 |
|---|---|---|
| 常驻记忆 | 当前会话作用域与预算，返回稳定快照、修订号和必要的来源摘要 | 宿主根据会话解析作用域 |
| 记忆变更 | 带条目 ID、预期修订号和来源的原子操作，返回已写入、待审核、冲突或容量状态 | 前台工具和桌面编辑复用宿主授权 |
| 历史搜索与翻页 | 查询条件和游标，返回范围内的消息片段、时间和定位 ID | 原始消息源在宿主，索引只供检索 |
| 复盘提交与审核 | 已提交的消息范围、检查点、审核人和确认后的改动 | 复盘可以提出改动，通过宿主服务提交自动批准的写入 |
| 新会话与刷新 | Bot ID 和聊天范围，返回新会话 ID 或确认现有会话获得新修订号 | 宿主管理运行时和既有记录 |

每次落盘成功后才更新界面和快照。索引采用可重建的检查点，搜索结果回源校验消息是否仍存在且可见。提案审批重新检查来源、访问权限及条目修订。自动提案提交、审核和用户编辑共用同一事务入口及重放约束。

现有 Link 能力枚举继续作为新入口的协商方式。原字段保持原有含义，新的响应将已保存条目、下一次注入预算及当前会话的装载回执分开返回。写入成功返回已提交的条目修订和快照状态。发生冲突时返回可重读的当前修订，客户端刷新后再提交。涉及修改或删除的关联提案按批次展示和批准，逐项保留来源。宿主仅向能展示整批差异的客户端开放批量决定。

## 迁移、删除和运行边界

### 旧笔记和日记迁移

1. 按 Bot 和范围建立迁移记录。每份旧笔记先按原始字节保存在宿主管理的备份目录，记录来源文件、内容摘要和迁移版本，备份仅供有权用户检查和导出。现有结构化库优先。若旧 Markdown 已被此前的镜像写入改过，备份如实标明当前可取得的版本。
2. 已知列表和人物段落导入对应类型。`Now:` 保留为单独的当前状态。未识别的段落保留原文及原始行范围并标记待整理。用迁移记录为未入库段落分配稳定 ID。校验备份摘要、解析覆盖和候选库条目数后发布权威库，镜像更新在发布之后进行。磁盘写失败时保留上次成功读取的版本。重启按迁移版本和来源段落继续，避免重复分配 ID 或覆盖新编辑。
3. 权威库切换后，结构化编辑和旧版全文设置都走同一写入服务。手工改动镜像由宿主检测，按已知版本比较并展示导入差异。导入时检查修订和预算，用户确认冲突后再写。用户可导出原始备份和当前条目。需要恢复的旧内容作为新修订导入，继续接受权限和撤回校验。
4. 旧日记以日期、来源文件和条目位置派生定位 ID。范围可判定的简记可按权限检索并标为「日记摘要」。有可核验原始记录时结果优先展示原话，摘要保留为补充。来源不明的条目放在仅宿主用户可查看的旧资料中。复盘和自动写入使用可核实的原始证据。

### 删除、撤权和备份

| 操作 | 即时失效和后续处理 |
|---|---|
| 忘掉一条 | 记录撤回标记，移除常驻条目和相关待审副本，阻止旧证据自动写回，在可确认的模型请求边界更新快照。原聊天和摘要仍可按权限回看。 |
| 清空某个私聊 | 停用该私聊历史、索引、队列、快照和复盘来源，分配新会话别名。保留长效笔记及其他群或项目。 |
| 删除原始内容 | 按原始记录 ID 撤销查看权限和引用，持久化删除标记，清理索引、复制的证据、待审及受影响的上下文缓存。仅有该来源支持的活跃事实和技能停止自动装载，等待用户确认保留或撤回。有独立来源的，只保留有效证据。 |
| 移除群成员、删除群或撤销项目授权 | 按 Bot 和范围停止运行和读取。撤销分享、原话链接和待处理作业。索引分片待清理时也必须在读取原文前检查权限。群成员撤出后，其他成员继续使用各自的授权。 |

授权检查以宿主已提交的范围状态为准。删除后从索引重建和复盘重放路径再次校验，避免内容回流。宿主管理的迁移备份显示保存范围，删除原文时同步处理该范围内的副本。备份仍含其他内容时按可定位段落清除，无法分离时在执行前说明受影响的备份范围。独立导出或宿主外备份的保留由其持有者管理。索引和回忆指标默认只记录数量、用量和延迟。

## 实现复核与后续设计

### 当前实现覆盖

- 桌面宿主按私聊和群分别运行 Bot，旧混合私聊继续通过历史投影浏览。归档的隔离私聊可续聊。Link 夹具覆盖活动别名、旧窗口控制限制和持久化发送回执。
- 常驻记忆包括用户偏好、自我、人物、群笔记和有授权的本地项目事实。桌面管理支持逐条修改、固定、忘记、原话查找、审核和共享撤回，展示候选注入预算与运行中的快照回执。后台复盘展示请求和字符用量，项目技能以已保存的成功工具证据为依据。
- 内置引擎在同轮压缩后更新系统提示，撤回按请求边界检查。外部 CLI 在下一轮发送前重载失效快照。历史搜索采用可重建的 Unicode 倒排索引，旧日记来源不明的摘要仅宿主可查看。本地设置可检查和导出私聊旧 Markdown 备份，预览导入差异，以新修订恢复可用旧条目。
- 原话删除覆盖宿主管理的群聊文本、群转私聊投递，以及内置引擎新建并独立保存的 Bot 私聊和 Bot 关联项目会话中的合格纯文本消息。宿主在实际写入进程退出后持有会话写入锁，再替换原始记录。撤回标记独立于档案保存，恢复旧档案时，含有已撤回消息的记录无法续聊。旧共享档案和带有无法完整处理的附件、压缩摘要、分支或派生副本的记录仍只提供原话查看。跨群回忆在桌面可打开命中的原话与邻近消息，打开时重新检查群成员资格和来源状态。可选 HTTPS 提供方支持只读检索。

### 忘记后的快照与界面状态

- 按范围保存条目删除标记和撤回位置，与条目删除一起原子提交。快照记录会话 ID、作用域、快照修订号及注入的条目 ID、修订号和当时文本。启动、刷新和压缩确认都核对删除标记。对仍在使用的快照只剔除已撤回条目，普通编辑继续冻结。迁移现有纯文本快照时保留可安全读取的旧版本。发生撤回后，无法逐条校验的快照从当前记忆重建并记录新修订号。
- 按会话、运行实例和请求绑定模型收到的快照。内置引擎在每次发起模型请求前检查撤回位置。已经发出的请求可以完成。压缩确认记录实际发送的版本，若该版本同时因撤回失效，继续等待有效快照，避免下次恢复旧内容。外部 CLI 在宿主可确认的轮次边界刷新，排队的新轮次等待确认。管理页分别展示当前装载的修订、下次快照预算和刷新状态。缺少可核实的装载记录时显示未知。
- 后台作业和待审提案记录生成时的撤回位置。展示、批准、自动写入和重放均重校验。受影响的关联提案整批失效并清除副本。撤回前的已知来源及文本指纹用于匹配旧事实，只有旧证据的提案一律退出自动写入，包括同义改写。跨越撤回位置的自动新增须有新的用户事实作为依据。文本指纹无法识别所有同义改写，无法确认的恢复由用户审核。用户明确要求再次记住时可以重新保存。原聊天和摘要仍可包含旧说法，删除原文走单独操作并清理索引和对应提案。

### 群聊复盘与跨范围授权

- 群自动复盘、桌面操作和 `bot_refine` 使用宿主解析的同一个群证据键。运行时会话 ID 用于校验发起方，群 ID 用于定位该 Bot 在群中的已完成消息。私聊依然按活动会话匹配。成员变更后重查证据和待审提案。
- 跨群回忆以用户在私聊发起的明确操作授权。用户可在私聊输入框发送 `/recall-group "规划小组" 红茶`。宿主精确解析带引号的群名或群 ID 和查询词。授权绑定宿主确认的用户消息、Bot、私聊会话、目标群、查询及当前轮次。歧义时返回可选目标，轮次结束或成员资格撤销时失效。普通提及、转述、否定、模型生成的指令和其他轮次的请求均不授予范围。查询、原话窗口和引用继续校验同一授权。跨群结果只用于已授权的回忆回复，复盘按原证据范围独立校验。
- 跨场合发送或共享记忆时由宿主核对用户确认的目标及实际内容。用户可通过 `/send-group "规划小组" 预检通过` 明确发送指定原文。发送模型草稿、附件和长期共享各自走宿主确认，授权绑定实际投递内容。批准后给目的范围建立有来源的投递或记忆记录。通用文件、搜索、Shell 和自定义工具必须受同样的数据边界约束。在宿主无法限制任意文件访问的运行时，聊天使用受限宿主工具，通用项目工具在单独授权的项目会话中使用。隔离验收覆盖运行时直接读写群存档的路径。

### Link 会话切换与交付顺序

- 每个逻辑会话保留历史定位的内部 ID。活动会话别名在跨进程重启、同会话刷新和冷恢复时保持稳定。开启新对话或从归档切换活动对话时分配新别名并主动推送更新。旧别名在其可见的历史范围内只读。终止、编辑、撤回排队和引用绑定活动别名及现有轮次或窗口标识。缺少轮次标识的旧端停止操作按「停止当前活动别名的当前轮次」解释。以 Bot ID 发起的旧版纯文本发送继续作为 Bot 收件箱入口。
- 归档续聊由用户从桌面的历史选择。宿主确认目标是同一个 Bot 的已隔离私聊、会话仍可读且当前没有进行中的回复或待发消息，再原子切换活动会话映射。保留目标会话的内部 ID 和有效快照。每次恢复为活动会话都分配新的对外控制别名，历史定位继续指向原始记录。切换失败时保留原活动会话。从旧混合记录开始新对话时只建立新会话，源记录仍按原投影查看。
- 宿主保留现有 Link 方法和字段。别名重新绑定时，宿主停止上一订阅的增量流，丢弃已失效的分页结果，新订阅从完整投影开始。旧端按当前别名停止轮次，没有携带会话或消息定位的操作仅按现有纯发送语义处理。新端按能力发送窗口或轮次标识。缓存有部分命中、会话切换或范围撤权时重新对齐，未读和输入状态从当前记录计算。
- 稳定请求 ID 的去重凭据与投递或队列接受记录一起落盘，回执先于模型派发返回。按配对设备、操作和请求 ID 查找回执，再核对目标范围和负载摘要。重试复用原操作结果，复用 ID 更换目标或内容时拒绝。清空、删除或撤权后，重放只能得到失效结果。群转私聊投递按源轮次和投递 ID 写入一条记录，时间线、未读和推送均消费该记录。旧端缺少请求 ID 时保留现有进程内去重，界面可在断线后先同步是否送达。

## 验收方式

用同一组脱敏脚本，在固定的 Hermes v0.23.4 和 BaoCode 候选实现上使用相同的模型、相近的上下文和固定的历史。分开测默认内置体验和启用可选提供方后的体验。下面列出桌面、宿主和本地运行时的验收项。

| 场景 | 验收信号 |
|---|---|
| 私聊记住偏好，关闭应用后再开 | 普通续聊恢复原快照，新会话装载最新记忆，设置页能找到来源。 |
| 纠正偏好并发生并发修改 | 旧修订无法覆盖新值，界面分别标出已装载和待刷新内容。 |
| 用户明确要求忘掉 | 闲置会话、下一轮及冷恢复均剔除撤回条目，包含撤回条目的并发压缩候选无法生效。原聊天仍可回看，旧证据的同义改写不会自动写回。 |
| 中文、英文和混合关键词回忆几周前的内容 | 返回原始措辞、正确来源和邻近消息，搜索时延可测。 |
| 隔离私聊、不同群和不同 Bot | 该范围外的词搜不到，模型请求、工具回执、提案、渲染内容均无串读。群聊 `bot_refine` 选择本群已完成证据。 |
| 显式跨群回忆、转发和共享 | 精确授权只允许指定操作。普通提及和伪造、过期或已撤销的授权被拒绝，通用工具无法绕开范围。 |
| Link 旧窗口跨活动对话切换 | 历史仍可读。执行 A → B → 恢复 A 后，第一次打开 A 时的别名和窗口回执均无控制权。新状态推送后，当前私聊和两个群照常收发。 |
| 发送落盘后丢失回执、宿主重启 | 相同请求 ID 重试得到原回执，时间线和未读只增加一次。变更目标或负载被拒绝。 |
| 旧笔记迁移中断、原文被删除或访问撤销 | 重试迁移保持原文备份、稳定 ID 和条目数。重建索引或恢复受管备份后，失效引用和已删除来源保持不可用。 |
| 人物重名、项目移动或删后重建 | 同名人物独立核对。项目事实跟随已授权的稳定 ID，删后重建的同路径项目没有旧授权。 |
| 复盘中包含同义内容、把别人的话当事实或提出删除 | 去重，区分事实与转述，重要变更正确进入待审。 |
| 整理出一份可复用的排查经验 | 默认自动保存并在新任务主动加载。开启待审时先显示依据和差异，通过后加载。覆盖锁定、并发修改及工具权限维持。 |
| 模型超时、宿主重启、请求重复提交和删除会话 | 对话可继续，提案幂等，删除后的历史查询和引用失效。 |

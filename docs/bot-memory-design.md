调研日期为 2026-11-24。Hermes 参照 [v0.23.4](https://github.com/NousResearch/hermes-agent/releases/tag/v0.23.4)，对应提交 `8fc0374447313e276f6b9a2764bfc750190c966a`。BaoCode 基线为 `9cdfca56`。本文以 Hermes 内置存储、历史搜索和默认自动复盘体验为对照，外部记忆提供方按配置单独验证。BaoCode 方案选择宿主统一管理记忆，私聊与各群分开运行模型上下文。沿用 Hermes 的写入默认值，普通记忆写入和自动技能维护直接生效，后台修改与删除长期事实进入待审。末尾给出工程量拆分和同任务对照验收。

## 用户体验目标

用户连续使用 Bot 时，可以直接说「以后记住」「这条已经变了」「把这件事忘掉」。用户需要能看到保存结果、来源和可见范围。Bot 应在新的对话中主动使用已经保存的事实，遇到具体往事时按需检索原话。用户结束一段有价值的工作后，Bot 能在后台提炼少量耐用结论，提醒用户查看需要确认的变更。重复完成相似工作时，Bot 可以找到经过验证的做法，并用它指导新的任务。

例如，用户在私聊说「每次发版先做预检」，Bot 将这个项目约定保存到正确的项目。下周用户说「我们把预检换成 `release check` 了」，Bot 更新现有条目。再开对话时，它使用新的命令。用户问「上次为什么要加这一步」，Bot 搜到当时的讨论，并能带你回到原话。它复盘时若发现发版流程可复用，可以自动保存一份有验证依据的技能，下次发版时按需加载。群里的 Bot 只能使用该群可见的对话、笔记和技能。

## 记忆写入和注入

建议由 BaoCode 宿主持有统一的记忆服务。Bot 工具、桌面和手机编辑、后台复盘都走同一套授权、变更和提示刷新逻辑。用户发话、宿主收到任务状态、编程 Agent 给出结果是不同的证据类型，保存时要保留区分。

一条记忆包含稳定 ID、内容、归属 Bot、作用域、类型、来源消息或任务、更新时间、修订号以及是否由用户固定。类型覆盖用户偏好、Bot 自我信息、人物印象和项目事实。长期笔记、当前 `Now:` 状态、待办提醒、历史消息与可执行技能分别使用各自的存储和生命周期。已有身份设定和共享用户资料可以显式标记为用户提供的内容。

- 模型工具提供列表、添加、定点修改和删除。修改和删除使用 ID 与预期修订号。模型可以在一个事务里合并几条重复笔记。相同内容的重复请求应具备幂等性。
- 用户明确要求记住、纠正或忘掉时，Bot 走对应动作并返回实际结果。模型主动发现可能矛盾的旧结论时，提交带来源的修改。如果用户和后台同时编辑，宿主退回过期提案，供复查后重新提交。
- 默认预算为用户偏好 1,375 字符、其余常驻事实合计 2,200 字符。常驻记忆批量写入按最终大小校验，超预算时返回当前条目和需要释放的空间，让 Bot 把合并与新增放在同一批提交。旧数据导入或缩小预算时保留超出的条目，桌面和手机标明常驻与待整理状态。模型上下文较小时另设总注入预算，通过中文对照数据验证。
- 注入使用确定顺序和稳定快照，方便复用模型前缀缓存。服务提交后发布新修订号，默认在新会话和支持的实时压缩边界装载。用户也可选择「刷新当前会话记忆」，保留历史并让下一轮采用新修订号。CLI 的刷新路径要验证保留会话 ID 和历史。工具在本轮返回新值。旧会话本身可能仍包含旧说法，提示要明确当前确认的条目是最新依据。
- 提供「开启新对话」入口。它停用当前上下文，保留老对话和来源链接，为同一个 Bot 建立新会话并加载最新快照。用户可以从历史重开原会话。这一入口独立于现有的「清空聊天」。
- 建议由事务型本地存储管理结构化记忆和待审变更，并以 Markdown 提供导入、导出和可查看副本。现有纯文本编辑接口在迁移期通过相同服务读写。实现前核对现有 Bot 文件的编辑方式，由统一服务协调所有写入。

## 历史回忆与作用域

宿主从已经落盘的消息构建可重建的本地全文索引。索引行保存来源类型、会话和消息 ID、角色、作用域和时间。默认索引用户发言和可见回复。开发日志、工具输出和隐藏推理使用各自的保留与授权策略。精确引用留在原始记录中，索引提供命中片段与可定位的原始 ID。

- 工具支持关键词、时间、项目、会话或聊天范围，返回若干命中和继续翻页的游标。用户可以点开原话，模型决定是否需要向前或向后浏览。历史索引的可见范围从当前上下文和宿主授权计算，搜索参数只负责进一步缩小范围。
- 中文需要单独验收。用本机 SQLite 3.51.0 的合成样本验证，trigram `MATCH` 可以找到「改喝红茶」，找不到两字词「红茶」，`LIKE` 可以找到后者。建议测试 CJK 分词或带权限和时间上限的短串回退，并覆盖路径、版本号、混合语言和跨标点短语。这个探针验证了本机 SQLite 行为，应用绑定与跨平台打包仍需验证。
- 现有同一个 Bot 的私聊和群聊会进入同一模型会话。因此，单给搜索结果加过滤仍会留下旧上下文。建议每个 Bot 保持统一身份，私聊与各群使用独立的模型上下文，各自只装载当前可用的记忆。用户在私聊明确选择一个自己可见的群，才引用该群往事。群里只看该群及用户明确分享的记忆。
- 作用域包括宿主上的 Bot/用户、项目、私聊和单群。手机 Link 身份和成员资格在上位服务层校验。群聊可用的工具也必须受到这条边界约束，涵盖通用文件读取、会话查询和能访问宿主数据的其他能力。旧的混合会话仅限有权的宿主用户查看，历史作用域明确的独立群记录可按原范围索引。

## 私聊与群聊拆分

### 桌面宿主的运行方式

1. **按场合选择会话。** 用 Bot ID 与聊天范围标识宿主线程。每个 Bot 有一个私聊范围，以及它加入的每个群各自的范围。私聊入口取得私聊线程，轮到 Bot 在群中发言时取得「该群 × 该 Bot」线程。模型选择、头像、身份和管理设置仍按 Bot 生效。宿主持久化范围到线程的映射，重启后按映射恢复。私聊入口沿用 `threadFor(bot)` 的入口形态，群聊显式传入群 ID。群运行目录使用宿主管理的独立路径，保留现有 Bot 资料目录作为身份来源。新旧目录有独立迁移规则，避开启动时仍会扫除的旧群成员目录。创建、恢复与会话替换都重新建立对应范围的监听。[现有线程选择](/Users/yimingd/Projects/baocode/lib/bots/bots.dart#L607) · [旧群会话清理](/Users/yimingd/Projects/baocode/lib/bots/bot_groups.dart#L148)
2. **发消息时就记录目标。** 私聊发送、群聊轮转和主动唤醒都在宿主记录消息来源、目标和轮次 ID。模型结束后按这次轮次的绑定发送结果，超时和图片缓冲也绑定同一轮，避免迟到的结果发错群。私聊保持现有基于 Bot 的已读与未读状态，群聊继续由群记录生成消息、序号、引用、输入状态和推送。默认保留同一个 Bot 同一时间只处理一轮的调度规则，群聊轮转继续排队。[群回合启动与调度](/Users/yimingd/Projects/baocode/lib/bots/bot_groups.dart#L913)
3. **在构造模型请求时限制可见内容。** 每个范围从其自己的会话、日记、历史查询与记忆快照取数据。群聊可以得到同一群的最近对话和明确共享的 Bot 资料。私聊中的用户偏好或项目数据需要明确分享才能进入一个群。私聊主人可以指名让 Bot 搜某个自己可见的群。宿主校验查阅权限并把结果送进私聊，手机现有输入框即可发出这项请求。
4. **让工具遵守同一范围。** 对搜索、原话读取、发往其他场合的消息、通用文件和会话访问，以及后台复盘使用宿主提供的轮次身份。自定义工具也按范围授权。群聊可用现有工具读取范围内的群记录，无法限定数据范围的工具需要由宿主拒绝用于群聊。群派发的输出默认发往该群。群聊通过 `bot_send` 合法发送私聊时，宿主生成一条有投递 ID 的私聊消息，供私聊历史、未读和时间线消费，重试时按 ID 去重。目前这类私信依靠共用会话里的工具结果显示。[现有跨场合发送](/Users/yimingd/Projects/baocode/lib/bots/bot_tools.dart#L491) · [现有私聊投影](/Users/yimingd/Projects/baocode/lib/link/chat_codec.dart#L34)

### 升级与老聊天

升级时把旧混合会话保留为历史来源，按已经可识别的私聊段生成私聊历史视图。新的私聊运行时从受限的启动上下文恢复，旧混合记录不作为模型的续聊输入。群聊继续读自己的持久化记录，保留消息序号、引用和附件映射。无法确定范围的旧内容由有权的宿主用户查阅，避免猜测归属后把它发给模型或出现在群里。

## 后台复盘与技能

复盘使用当前作用域内已经稳定提交的对话、任务终态和相应证据。建议把它作为独立的宿主任务运行。手动「整理记忆」提供可选关注点。自动复盘默认在累计 10 个有效用户轮次或 10 次含工具调用的迭代后触发，并在前台回复完成后执行。开启新会话和压缩会话会更新记忆注入的边界。按任务完成事件额外触发复盘作为 BaoCode 的可选设置，默认采用与 Hermes 一样的轮次和工具调用阈值。外部运行时只统计可观测的事件。

为每个会话记录上次处理的位置，手动触发以外的重叠请求合并处理同一段消息。作业使用独立 ID 和有上限的重试。宿主重启可恢复已接收的任务，前台聊天优先使用模型资源。预设限额覆盖每次复盘的消息量、输入和输出预算及并发数。默认复用前台模型，用户可指定单独的复盘模型。

模型输出结构化提案，每条包含新增、替换、删除或技能草案，附上依据、归属范围和当前条目修订号。宿主校验来源可见性、大小、重复和冲突，再决定是否提交。对话中的引用和工具回显作为证据处理，写入能力由复盘运行器限定。提交逻辑复用前台记忆服务，避免一次复盘直接改写整份文件。

对齐 Hermes 的记忆写入默认值。前台操作和无冲突的后台新增条目直接保存，并在状态里可见。后台替换、删除进入待审。用户可以开启全部待审或关闭自动复盘，仍可手动运行。扩大可见范围由用户明确授权。提案只被采纳一次，重复复盘后发现同一事实时合并证据。[Hermes 记忆写入设置](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/tools/memory_tool.py#L179)

技能记录包含适用项目、触发条件、验证过的步骤、验证结果、依赖和来源。复盘先检查相近的已有技能，优先更新现有做法。对齐 Hermes 的 `skills.write_approval: false`，通过项目作用域、锁定状态和修订检查的技能变更默认写入，并保留来源和变更记录。用户可以开启技能待审，在手机或桌面查看差异再逐项确认。后续会话只按任务的项目和适用条件加载相关技能，执行沿用项目已有工具权限。自动写入服务校验技能文件和运行时能力，禁止技能通过 front matter 新授工具权限。项目约定可以作为事实，含条件和步骤的成熟做法才进入技能。[Hermes 技能写入设置](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/features/skills.md#L669)

技能维护参考 Hermes Curator。它默认跟踪自建技能的使用，14 天未用标记为陈旧，30 天可归档，固定的技能可以免于自动归档。可选的模型合并和恢复是独立能力。BaoCode 可给模型产出的技能提供固定、锁定、可恢复归档及修订记录，合并只在有审阅的情况下应用。代码库已有技能、用户手写技能和外部安装技能沿用各自的管理权限。[Hermes Curator](https://github.com/NousResearch/hermes-agent/blob/v0.23.4/website/docs/user-guide/features/curator.md#L33)

外部提供方按宿主和 Bot 显式启用，并分别声明检索、写入、保留和删除能力。内置记忆在提供方不可用时仍可读写。用户在启用前可以看到由谁处理数据、发送哪些内容以及是否保存对话。提供方返回的文字按检索结果处理，模型服务和存储位置在设置中分别可见。对照验收以 Hermes 内置配置为基线。如果目标体验来自某个外部提供方，需要用该提供方和同等的配置单独验收。

## 服务接口与一致性

| 入口 | 输入和结果 | 谁拥有写入权 |
|---|---|---|
| 常驻记忆 | 当前会话作用域与预算，返回稳定快照、修订号和必要的来源摘要 | 宿主根据会话解析作用域 |
| 记忆变更 | 带条目 ID、预期修订号和来源的原子操作，返回已写入、待审核、冲突或容量状态 | 前台工具和手机编辑复用宿主授权 |
| 历史搜索与翻页 | 查询条件和游标，返回范围内的消息片段、时间和定位 ID | 原始消息源在宿主，索引只供检索 |
| 复盘提交与审核 | 已提交的消息范围、检查点、审核人和确认后的改动 | 复盘可以提出改动，通过宿主服务提交自动批准的写入 |

每次落盘成功后才更新界面和快照。索引采用可重建的检查点，搜索结果回源校验消息是否仍存在且可见。提案审批重新检查该来源是否存在、访问权限是否仍有效、条目修订号是否已变化。自动提案提交、审核和用户编辑统一使用这组约束，避免恢复失败任务时把已删除的内容写回。

## 迁移、删除和运行边界

迁移前保留现有 Markdown 原文，逐 Bot 解析已知结构，给条目分配稳定 ID。非标准段落作为原文条目导入，显示待整理标记。迁移过程支持重复运行。完成一轮事务并核对条目数及原文后再切换读取。旧日记保留为可查询的简记，日志来源能定位时优先引用原始消息。

「忘掉一条」移除活跃笔记、待审副本和自动注入。原聊天仍可通过历史找到，因此 UI 应明确提供与「删除原始内容」不同的操作，并允许主动忘掉的事实在后台复盘里停用重新提炼。清空会话、删除群、删除项目或撤销访问时，索引、上下文缓存和待审来源需要同步失效。指定删除原始内容时，同时清理索引和提案中对应的内容，并说明宿主备份的保留策略。

如果使用外部模型，后台复盘会产生额外模型请求。设置中应看到复盘所用模型、预计成本上限、暂停开关和失败原因。索引及回忆指标默认记录数量、延迟等统计，记录正文需要另有明确用途。

## 验收方式

用同一组脱敏脚本，在固定的 Hermes v0.23.4 和 BaoCode 候选实现上使用相同的模型、相近的上下文和固定的历史。分开测默认内置体验和启用可选提供方后的体验。下面是拟议的验收项，需运行对照后填写成绩。

| 场景 | 验收信号 |
|---|---|
| 私聊记住偏好，关闭应用后再开 | 新会话主动采用已保存的偏好，设置页能找到来源。 |
| 纠正偏好并发生并发修改 | 只出现最新确认的值，冲突提示保留较新的修改。 |
| 用户明确要求忘掉 | 新会话恢复为无该条记忆，后台复盘处理旧会话后仍不会自动重新记住。 |
| 中文、英文和混合关键词回忆几周前的内容 | 返回原始措辞、正确来源和邻近消息，搜索时延可测。 |
| 隔离私聊、不同群和不同 Bot | 该范围外的词搜不到，模型请求、工具回执、提案、渲染内容均无串读。 |
| 复盘中包含同义内容、把别人的话当事实或提出删除 | 去重，区分事实与转述，重要变更正确进入待审。 |
| 整理出一份可复用的排查经验 | 默认自动保存并在新任务主动加载。开启待审时先显示依据和差异，通过后加载。覆盖锁定、并发修改及工具权限维持。 |
| 模型超时、宿主重启、手机重复提交和删除会话 | 对话可继续，提案幂等，删除后的历史查询和引用失效。 |

对照记录记忆正确率、陈旧事实率、引用准确率、搜索耗时、每百轮的复盘成本、需要处理的提案数量、跨范围串读次数及技能带来的步骤减少。对权限和删除语义使用确定性测试，生成行为使用固定脚本反复验证。当前完成了源码调研与本机中文搜索探针，端到端对照和成本数据留待实现验证。

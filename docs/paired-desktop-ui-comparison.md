# 本地与配对远程桌面：界面对照和复用清单

范围是桌面工作台的本地会话与「我的电脑」里的配对远程会话，不把手机 Link 或 IDE 的 SSH 工作台当成远程会话的同义词。远程功能范围另见 [Paired desktop coverage](paired-desktop-coverage.md)。

## macOS 实机观察

在隔离数据目录构建并运行 macOS 桌面应用，用同一个合成项目、会话、消息和 Git 工作树对照本地与远程。两端使用生产 Workbench，配对使用 `LinkHost` 与 `WorkspaceBridge`，底层为 MemoryLink，不等于两台物理电脑通信。用现有 `PerfInput` 驱动；`screencapture` 无法生成指定窗口图像，改用运行中 Flutter 窗口的渲染帧。观察了 1360×820 和 520×740 两种窗口，均为深色。

- 宽屏下两边的正文、消息气泡和回复操作样式接近。差异集中在顶部栏、左栏宽度和选中样式、对话外框，以及输入区工具栏和底栏。远程「我的电脑」和连接状态是必要差异，目录行与面板布局无需因此另做一套。
- 窄屏下两边都能显示消息。远程打开右栏后切成完整项目面板，关闭可以回到会话。右栏断点、返回和焦点应成为共享容器的明确规则，不能只统一宽屏外观。
- 同在 1360 像素宽的窗口，本地文件区并排放树与预览，远程先把文件树铺满右栏。本地 Git 的提交列表与提交表单横排，远程在右栏上下堆叠。远程点开同一工作树改动后直接显示 patch 原文。可先统一文件树／预览的布局、Git 列表和提交表单，再完善 patch 阅读。会话审阅已共享另一条 diff 渲染路径。
- 驱动在本地和远程的编辑器中输入了同一份草稿，均通过断言。顶部、侧栏、文件与 Git 的观察来自深色项目会话。浅色、Bot／群聊、审批、媒体、任务交互来自源码盘点，仍需成对验收。
- 同一合成回复在两端 token 数量相同，但显示费用不同。需单独核对显示值来源；截图不能证明实际计费有误。

## 统一后复测

在同一个隔离 macOS 工作台重跑宽／窄窗口，以及 Bao Dark／Bao Light。每种主题各通过 9 组交互检查：两端输入同一草稿、浏览相同文件和 Git 历史、打开远程只读文件与着色 patch、缩窄时右栏让位、手动重开后关闭且保持草稿。截图是原生窗口内的 Flutter 渲染帧，不含系统窗口外框。

## 复用清单（改造前基线）

| 区域 | 已复用／仍各自实现 | 建议共用的界面 | 保留的远程边界 |
| --- | --- | --- | --- |
| 工作台外壳 | 两个页面入口，各自排布导航、对话与活动区 | 三栏容器、面板间距和分隔、断点策略、拖拽手柄与焦点路由 | 主机切换、断线、等待授权，以及本地工作台命令隔离 |
| 左侧导航 | 行级控件和时间格式部分共用；宽度、窄屏、项目树和菜单分别组装 | 侧栏容器、目录树层级和行、展开／选中／悬停、行内动作、同语义菜单 | 「我的电脑」入口、可见项目和会话目录由主机提供；远程删除等操作单独确认 |
| 会话标题 | 项目会话共用 `ConversationCardHeader`；标题操作分别组装 | 统一按钮槽、溢出菜单和标题编辑的呈现 | 连接状态和远程主机可执行的动作 |
| 项目消息 | 已共用 `ChatHistoryView`、气泡、富文本和 minimap，远程经 `PagedChatFeed` 接入 | 保持一个渲染入口；补对照测试，不再复制消息列表 | 远端分页、引用和附件权限；不可把主机路径交给本地文件打开器 |
| Bot／群聊消息 | 远程维护自己的列表和消息行，只复用部分消息正文 | 先共享消息行、头像、时间、引用、回复和媒体入口，再评估 feed 是否能共用 | 发言者、群聊序号和引用、分页、群聊与私聊隔离 |
| 输入区与状态 | 共用 `ComposerSurface`、发送按钮和部分选择控件；编辑区、工具栏和底栏各组装 | 布局、附件条、模型／权限选择器位置、发送／停止状态、键盘与 IME 规则、分支与上下文状态的展示 | 远程 ACK、重连、失败保留草稿、上传、主机能力和排队状态 |
| 审批、提问、计划 | 已部分共用 `InteractionPanel` 等；动作和状态各自接线 | 内联审批／问题、计划卡片、长内容和按钮状态 | 主机校验请求 ID 和能力；不把本地可用操作自动开放给配对客户端 |
| 右侧活动区 | 共用 `ActivityStrip`、`SidePanelSectionBar` 等；停靠、宽度及窄屏页分别实现 | 面板容器、标签栏、拖拽、关闭／返回、焦点、列表密度和滚动 | 独立的页面集合、权限和连接生命周期 |
| 文件树和文件预览 | 远程有自己的文件树与预览流程 | 行、图标、展开、选中、空态与预览框；切换不同内容时的布局规则 | 远程目录按需请求、命名根、文件大小和类型限制、只读或下载 |
| 变更审阅、Git 与 diff | 部分 diff 渲染控件共用；列表、详情／历史、操作条仍有分叉 | 变更行、状态和计数、Git 历史／提交详情、diff 容器、审阅工具栏 | 会话审阅与仓库 Git 分开；远程读写按主机声明的能力及审阅 revision，不引入客户端 Git 执行 |
| 任务、输出和终端 | 本地终端与远程任务输出是不同能力 | 可共用任务列表、日志外壳、跟随／复制、加载和空态 | 远程任务尾部输出不等于交互式终端，不为视觉对齐扩大能力 |
| 媒体、扩展与人员设置 | 远程有单独的数据和入口 | 图片／富文本预览外壳、扩展清单卡片、Bot／群聊配置表单；按功能拆 | 媒体先校验再渲染，扩展库存可能只读；电脑与配对管理仍独立 |
| 通用横切状态 | 部分共用控件，菜单、提示文案和加载／空状态仍在不同页面组装 | 同一套主题 token、列表密度、空态、错误／重试、确认框和快捷键提示 | 保留准确的主机错误和重连提示；不可用操作按能力隐藏或禁用 |

## 实施顺序和验收

1. 先合并会话工作台的布局契约：标题和左右容器、窄屏、拖拽与快捷键作用域。沿用现有工作台组件，做成接收内容和动作的呈现层，不新建第三套工作台。
2. 在共用容器里替换右侧文件、Git、变更及 diff 的重复呈现。让本地／远程分别提供数据及回调。再清理左侧同语义的项目／会话行和菜单。
3. 统一 composer 和状态条的呈现和通用输入行为。保持两端的提交状态机独立，并保留远程 ACK、草稿、IME、断线／切主机回归用例。
4. 项目消息维持现有共享入口；然后收敛 Bot／群聊行和共用预览、表单。不强行把群聊的分页、引用或发言者映射成项目工具消息。
5. 用同一个 fixture 同时渲染本地、远程。宽／窄、浅／深、中文文本、选中／悬停、焦点、长内容和空／错误状态逐项对照。对等能力下应走同一呈现组件，而不只是两张截图相似；远程独有或受限能力按各自测试断言。完成一处替换后删除旧呈现实现。

## 容易误合并的界面

- **会话审阅和仓库 Git diff**：会话审阅两边已共用 `IdeCodeDiff`，保留主机 revision 校验；远程 Git 当前收到统一 patch 文本，先共用文本着色、导航和空态。完整双栏要等主机能提供两侧内容。仓库暂存、提交等动作按现有 host RPC 和能力显示，不从本地 Git 页继承默认写权限。
- **文件与任务预览**：远端文件树已共用 `IdeViewTitle`、`IdeListRow` 和文件图标，但文本内容仍用 `SelectableText`。复用本地的只读内容呈现，不接本地编辑或文件系统。任务输出可共用 ANSI／滚动／复制呈现，不接 PTY 输入。
- **审批和菜单**：提问已内联使用 `InteractionPanel`，工具审批仍有远程对话框和扁平文本预览。可复用结构化预览和菜单样式，远程仍限定当前请求 ID 与单次批准／拒绝。电脑入组审批不并入会话审批。
- **媒体和权限**：优先共用支持 loader 的图库、缩放和导航。保留按会话解析、内存图像和切会话后的过期响应检查。客户端只展示已知项目路径，此限制不等于主机协议的文件沙箱。

## 成对验收场景

- 导航：同一目录树、两个项目和同名会话。比较宽屏与窄屏、展开与选中、右键菜单；切换主机或返回本地后检查选中项和快捷键没有串场。
- 对话：同一 Markdown、代码块、长消息与图片。比较正文宽度、溢出、选择、复制和 minimap；另测远程分页和媒体打开策略。
- 输入和审批：用同一草稿、附件、模型选项和待确认问题；比较工具栏、发送／停止、中文 IME、键盘焦点。另测迟到 ACK、断线和不支持的主机操作。
- 活动区：同一文件树、长文件名、改动与 Git 提交。比较拖拽、滚动、标签切换、空态／错误、文件和 diff；区分只读仓库历史与可操作的会话审阅。
- Bot／群聊：同一头像、时间、长正文、引用和附件；比较消息行的布局，单独验证群聊分页、引用未加载和发言者显示。
